CLI & DIAGNOSTICS

Run DoesCap straight from your terminal, verify tokens end-to-end against hCaptcha's official API with devtest.py, and review production operational notes.

COMMAND LINE USAGE

Installed as the doescap CLI command: 

# Basic execution
doescap --sitekey "10000000-ffff-ffff-ffff-000000000001"

# Full flags reference
doescap --sitekey "..." \
  --rqdata "OPTIONAL_RQDATA" \
  --host "0.0.0.0" \
  --port 8989 \
  --timeout 180 \
  --title "DoesCap CLI" \
  --browser "chrome" \
  --custom-html "./my_ui.html" \
  --assets-dir "./assets" \
  --no-browser

LIVE BACKEND VERIFICATION (devtest.py)

The repository includes devtest.py for end-to-end testing against hCaptcha's official https://api.hcaptcha.com/siteverify endpoint using hCaptcha's public test keypair: 

# Run interactive verification test (default test sitekey 10000000-ffff-ffff-ffff-000000000001)
python devtest.py

# Or test with your own sitekey, secret, and port
python devtest.py --sitekey "YOUR_SITEKEY" --secret "YOUR_SECRET" --port 8787 --timeout 180

After you solve the challenge in the browser, devtest.py submits the token to /siteverify, prints the JSON validation response, and updates the browser panel via mark_claimed().

PRODUCTION NOTES

  • No authentication — treat relay endpoints as local-only bearer services.
  • Direct mode operates at native monitor/display refresh rates (60Hz – 144Hz) with 0ms synthetic input lag.
  • Network pairing: phones on the same Wi-Fi can open relay.relay_url to solve challenges for headless hosts. On Windows, allow_firewall_rule=True attempts to allow the active port through Windows Defender Firewall.
  • Deferred shutdown: calling mark_claimed() keeps the HTTP server alive for 25s (and mark_failed() for 10s) so the browser UI can display and copy any reward code before close() runs.
